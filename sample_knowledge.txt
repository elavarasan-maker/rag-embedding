RAG combines information retrieval with language generation. Documents are loaded and split into chunks. Chunks can be transformed into embedding vectors and stored in a vector database. A user query is embedded and relevant chunks are retrieved using similarity search. Retrieved text is placed in the prompt as context. The model generates an answer grounded in that context. RAG can reduce unsupported answers but does not guarantee truth. Chunk size, overlap, metadata, document quality and retrieval strategy affect quality. Embeddings map text to numerical vectors. Cosine similarity is a common vector comparison method.
